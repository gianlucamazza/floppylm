# Xbox E0 backend

S1-S10 are accepted in ADR 0008. ADR 0009 selects the separately packaged Xbox
DX12 trainer; ADR 0010 records the independently accepted numerical gates.

Python owns the byte corpus, initial weights, ordered NumPy sample indices,
FLP2 serialization and sliding evaluation. The native app receives training data
only. CPU fixtures are useful diagnostics; hardware acceptance requires console
outputs, positive dispatch counts, exact resume equality and measured memory.

## Commands

```bash
python experiments/xbox_acceptance.py --out runs/xbox-acceptance-UNIQUE
python experiments/e0_v2.py --run --smoke --backend xbox
python experiments/e0_v2.py --run --backend xbox \
  --xbox-acceptance runs/xbox-acceptance-UNIQUE/acceptance.json
python experiments/e0_v2.py --grid --jobs 1 --backend xbox \
  --xbox-acceptance runs/xbox-acceptance-UNIQUE/acceptance.json
python experiments/e0_v2.py --retry RUN_ID --xbox-acceptance ACCEPTANCE_JSON
```

The scientific gate binds acceptance to the exact installed package and source
commit. Chunk uploads and downloads are SHA-256 verified. All three cooldown
artifacts are downloaded before Python emits canonical FLP2 and val scores.
Cancellation writes a per-job marker. Controlled acceptance interruption uses a
native checkpoint; the resumed response must carry the new submitted job hash.
The final test uses an exclusive durable reservation before opening the test split.

## Earlier package evidence

- Independent held-out reference: 36 model/scale/MLP/QK cases and a three-step
  identical-gradient AdamW oracle passed on the host.
- CI run 36743191762 built the Release UWP package at commit
  `da4b391b033949b0880c4d93526151bdec44c11a`.
- That package was installed on a retail Xbox Series S in Dev Mode. Its first
  device initialization selected WARP; acceptance correctly stopped.
- CI run 36744081513 adds adapter-specific diagnostics and disables the debug
  layer in Release UWP. Hardware acceptance remains pending this retest.

Installation repacks the unsigned CI payload with OpenAppx and signs it with the
existing development certificate. Every executable, shader, resource and manifest
entry is checked byte for byte against the downloaded CI package. ZIP metadata,
block map and signature are generated by the packager; their hashes are recorded
separately. Neither installation nor CI success is a scientific training result.

The `0.1.0.8` package passed all 36 GPU fixtures, the on-console identical-input
optimizer oracle and exact uninterrupted/resumed weights and moments. Full evidence:
`runs/xbox-acceptance-20260930-ci36745050129/acceptance.json` (local ignored artifacts).
A representative ctx=256/batch=32 trial failed atomic JSON replacement; this is an
operational failure, not a quality or throughput result. The newer build retries
only brief sharing/lock conflicts, preserves failure telemetry and resets GPU
counters per job. It must pass the console gates again before campaign execution.

If Device Portal retains more than one package version, set `XGPU_E0_PACKAGE` to
the explicit package full name from the acceptance proof. Ambiguous discovery
fails instead of choosing an unvalidated version.

The sequential `experiments/e0_campaign.py` freezes the neutral shape, two neutral
seeds, six recipes per arm, solver grids and five paired seeds before results.
Its worker lock prevents concurrent launch; stable exclusive run identities prevent
silent retraining when reopened. A failed comparison gate stops the campaign.

## Current kernel validation

The E0 backend now contains only the attention operations used by the model:
Scores, causal Softmax and Weighted. The unused fused implementation has been
removed from both CPU and HLSL; operation IDs are contiguous with no compatibility
alias. Device Portal discovery requires its actual `InstalledPackages` response.
Backpropagation for the active model remains required.

Independent per-operation PyTorch/autograd fixtures exposed future-position
Weighted gradients and cancellation in shifted-logit cross-entropy. Their failed
baseline is retained in `runs/kernel-baseline-20260930T171719Z-0be030`.
Both defects were corrected without changing the approved numerical thresholds.
All 52 active-operation cases and the full 143-test host suite pass after cleanup.
Scientific submissions now also require a successful per-operation hardware proof.
CI run `36751689355` installed package `0.1.0.19` from PR merge commit
`6dbc407`; its tree equals branch source `762628a`. All 52 operation cases,
36 model fixtures, identical-input AdamW and exact checkpoint resume passed on
Series S. The earlier package proof above does not cover these changes.
See [the new package evidence](evidence/xbox-e0-20260930-kernels/notes.md).

The new representative synthetic trial completed at 959.012 token/s,
153.758 seconds wall time and 91,238,400 bytes peak app memory.

## Scientific execution and recovery (2026-10-01)

ADR 0011 records the owner's exclusion of tensor16 from scientific E0. The
campaign compares row16 and row8log; the codec diagnostic remains available.
Use the same installed package `0.1.0.19` and its acceptance/benchmark evidence.

```bash
python experiments/e0_campaign.py --out runs/e0-campaign-UNIQUE \
  --acceptance runs/xbox-acceptance-20260930-ci36751689355/acceptance.json \
  --benchmark runs/xbox-benchmark-20260930-ci36751689355/summary.json
python experiments/e0_v2.py --resume RUN_ID --xbox-acceptance ACCEPTANCE_JSON
# Reopen the campaign with --recover to recover existing bound trials.
```

Training corpora are shared by hard link on the same filesystem, with content
hashes binding every job; prepared data must remain immutable. Transport loss is
logged and retried up to five consecutive failures, without cancelling GPU work.
An explicit interrupt cancels the job. Recovery verifies package, acceptance,
recipe and asset hashes before reconnecting or using a verified checkpoint.
Failed native jobs require diagnosis. Existing evaluated branches are hash-checked
and reused; completed recovery does not repeat evaluation. The final-test exclusive
reservation remains mandatory and is never reset automatically.
