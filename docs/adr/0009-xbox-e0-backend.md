# ADR 0009: Xbox GPU execution with an independent Python oracle

## Status

`superseded-in-part` — accepted 2026-09-30, through approval of the implementation plan, amended 2026-10-01.
Supersedes in part [ADR 0004](0004-miniature-budgets.md): the CPU-only execution requirement for E0 at 1/16; other budgets are unchanged.
Superseded in part by [ADR 0010](0010-independent-numerical-gates.md): the numerical acceptance paragraph.
Amended by [ADR 0012](0012-repo-boundaries.md): repository ownership boundaries and closure of xllama PR #301.

## Context

The owner selected xbox-gpu-training and a dedicated Series S in Dev Mode. Its current
Win32 tiny-network smoke is not a transformer trainer or a deployable Xbox package.
Its FakeQuant, clipped STE, RMSNorm epsilon, optimizer and WSD differ from this bench.

## Decision

- FloppyLM owns data, configurations, minibatch indices, initial fp32 weights, FLP2
  serialization, evaluation and scientific gates. xbox-gpu-training owns DX12 execution,
  portable checkpoints and a separate UWP package. xllama is not modified.
- The E0 backend implements the existing Python model and codec semantics, including
  identity STE, fp16 stored scales/norms, PyTorch fp32 RMSNorm epsilon, tied embedding,
  causal attention, all three MLPs and optional QK norm.
- AdamW uses betas (0.9, 0.95), epsilon 1e-8, decoupled decay on QLinear parameters
  only and global gradient norm clipping at 1. Master weights and moments remain fp32.
- Python supplies the initialization and a deterministic index plan generated by the
  existing DataStream RNG. The console reads corpus windows from disk. Test data never
  enters training jobs. Checkpoints include all optimizer and stream state.
- Versioned jobs bind config, initial tensors, corpus and index plans by SHA-256.
  Transfers are resumable; submitted jobs and retrieved results are verified.
- The Series S package is x64 UWP, Release/non-debug, with a 1 GiB memory planning
  budget and one GPU job at a time. CPU/WARP fallback cannot certify Xbox GPU results.
- Scientific cooldowns copy the trunk at T/2T/4T branch points and never update it.
  Selection and saturation refer to the same 4T artifact.
- Exact equality is required for quantized symbols and scale encodings. Numerical
  kernel parity uses the existing GPU-track gates: max absolute error 1e-5 and
  relative error 1e-4 for reference magnitudes >= 1e-2; smaller values are abs-gated.
  Report errors per operation, logits, loss, gradient and optimizer state. Never
  relax a failed gate after observing results; a change requires a superseding ADR.
- The Python checkpoint-resume test remains an independent oracle. On Xbox, resumed
  and uninterrupted execution of the same backend must reproduce identical state.
- Dedicated console time has no prefixed cap. Measure sustained throughput before
  the campaign; report runtime estimates, dispatches, transfers and peak memory.

## Consequences

Backend acceptance precedes E0. A package, passing host smoke or CI success alone is
not hardware validation. Failure of correctness, memory or scientific gates stops
the affected stage and produces evidence, not a validated baseline.

## Alternatives

Running the existing tiny-network smoke as E0, substituting its clipped STE/absmean
quantizer, or silently falling back to CPU would change the experiment and is rejected.
